# 天下无拐 接口契约 v1

> 单一事实源。`guard-find-app` 的 `lib/api/endpoints/**` 类型与 `guard-find-server` 的 Controller/Req/Resp **都必须从本文件派生**;任何一侧要改字段,先改本文件并同步另一侧。
> 契约来源:`guard-find-server/openspec/changes/add-guardfind-mvp-phase1/specs/**`、`guard-find-app/openspec/changes/add-guardfind-mvp-phase1/specs/**`、`doc/天下无拐App整体功能规划书.md`。
> 版本:v1 | 更新:2026-09-24

## 0. 通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `lib/env.API_BASE_URL`(dev 指向 `http://<host>:8082`,生产强制 HTTPS) |
| 实时通道 | `lib/env.WS_BASE_URL` + `/websocket?token={appToken}` |
| 响应包裹 | `{ "code": "0", "msg": "操作成功", "data": <payload>, "success": true, "timestamp": 1790307822221 }` |
| **`code` 类型** | **字符串**(框架 `top.continew.starter.web.model.R#code` 为 `String`)。客户端 MUST 用 `String(code) === '0'` 判定成功,MUST NOT 与数字比较 |
| HTTP 状态 | 恒为 200(含业务失败);仅网关/白名单错配时才可能出现非 200 |
| C 端鉴权 | 请求头 `Authorization: {token}`;token 由 `POST /app/auth/login` 签发,Sa-Token `loginType=app` |
| 分页(列表) | 入参 `page`(1 起)、`size`;出参 `PageResp{ records: T[], total: number }` |
| 分页(信息流) | 入参 `cursor?`、`size`;出参 `FeedResp{ records: T[], nextCursor: string\|null, hasMore: boolean }` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`(日期字段 `yyyy-MM-dd`),时区 Asia/Shanghai |
| ID | 字符串承载(雪花 ID 超出 JS 安全整数),服务端序列化为 string |
| 字典值 | 大写蛇形枚举字符串,选项一律由 `GET /app/plaza/filters` 提供,前端不硬编码 |

### 错误码

取值分两层。**框架层**由 `GlobalExceptionHandler` / `GlobalSaTokenExceptionHandler` 产出,是 HTTP 状态码样式的字符串;**业务层**由 `AppBizException` 显式携带,用于客户端需要专门交互的分支。两层的取值不重叠。

| code | 层级 | 触发条件 | App 处理 |
| --- | --- | --- | --- |
| `"0"` | 框架 | 成功 | — |
| `"400"` | 框架 | 参数校验失败(`BadRequestException`、jakarta 校验、缺参) | 定位到具体字段并展示 `msg` |
| `"401"` | 框架 | 未登录 / token 失效(Sa-Token `NotLoginException`) | 清会话 + 跳登录(带 `redirect`),**全局只触发一次** |
| `"403"` | 框架 | 已登录但无权限(`NotPermissionException` / 越权) | 无权限态,不跳登录 |
| `"405"` | 框架 | 请求方式不支持 | 视为客户端缺陷上报 |
| `"500"` | 框架 | 通用业务异常(`BusinessException`)与系统异常 | 展示 `msg`(服务端已写好可读文案)+ 重试 |
| `"4002"` | 业务 | 状态冲突(非法状态跃迁、目标档案状态已变) | 刷新后重试 |
| `"4003"` | 业务 | 业务规则拒绝(缺体貌信息、未勾选合规告知、图片超量、非本人操作) | 展示 `msg`,定位到触发字段 |
| `"4005"` | 业务 | 疑似重复档案,`msg` 内列出命中的档案编号 | 弹确认框,用户确认后带 `forceSubmit=true` 重提 |
| `"4006"` | 业务 | 账号锁定(连续密码错误达阈值) | 展示剩余锁定时间 |
| `"4290"` | 业务 | 触发限流,`msg` 内含建议等待秒数 | 禁用提交并倒计时 |

> 变更说明(2026-09-25):本节原先把 `code` 写成数字,并列出 `"404"`(资源不可见)、`"429"`(限流)、`4001`(校验)等取值。实测 `R.code` 是字符串,且框架不会为"已下架档案"单独产出 404 —— 它走 `BusinessException` 即 `"500"`。因此:
> - **资源对外不可见**(详情直链访问 `OFFLINE`/`ERASED` 档案)实际返回 `code="500"`、`msg="该信息不存在或已下架"`。`plaza-feed` 规格里"返回 404 且带说明"这一句按此实现理解,HTTP 状态仍为 200。
> - 业务层码需要服务端显式抛 `AppBizException` 才会出现;尚未接入的分支目前会以 `"500"` + 可读 `msg` 返回,客户端按 `msg` 展示即可,不要依赖业务码存在。

## 1. 账号与会话(`/app/auth`)

### 1.1 `POST /app/auth/sms-code` 公开

```jsonc
// req
{ "phone": "13800001234", "scene": "LOGIN" }   // LOGIN | RESET | BIND
// data: null
```

`isNewUser=true` 时 App 展示非阻断的资料引导。

### WebSocket 帧

```jsonc
{ "type": "message", "data": Message }        // 定向站内信
{ "type": "ping" } / { "type": "pong" }        // 心跳
```
仅推送给该 `userId` 对应的连接。断线超过 10 秒 → App 改 30 秒轮询 `/app/message/unread`;进后台停止,回前台立即补拉一次。

## 9. 一致性核对清单(交付时逐项打勾)

- [ ] App 侧 `lib/api/endpoints/**` 的每个路径与方法都能在本文件找到
- [ ] 后端 Controller 的 `@RequestMapping`/`@CrudRequestMapping` 路径与本文件逐字一致
- [ ] `CasePublic` 不含 `address`、`contactPhone`、`missingTime`(精确到日)任一字段
- [ ] 所有列表/游标分页的 `records` 元素结构与本文件一致
- [ ] `code`/`4001`/`4290` 等错误码在服务端有对应抛出路径,App 侧有对应处理分支
- [ ] 未登录可访问集合 = `{/app/auth/sms-code, /app/auth/login, /app/auth/reset-password, /app/plaza/**, /app/search, /app/find/case/{id}, /app/common/dict}` 且已登记 `security.excludes`
