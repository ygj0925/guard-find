# 租赁产品与运营发布升级设计

调研日期：2026-11-18。范围：guard-find 后端、管理后台、微信小程序；不修改独立的社区 App。

用户已确认本阶段采用小程序内手写签约；尚无抖音开放平台应用、小红书发布权限或发布服务商，先交付发布中心与接入配置。本文记录设计和外部接入边界，具体部署变量、数据源及测试结果见对应模块说明。

## 1. 产品判断与竞品调研

| 参考对象 | 核验到的能力 | 本项目采用的设计 |
| --- | --- | --- |
| 贝壳/链家在线签约 | 官方政策说明了在线合同保管、实名信息核验、第三方电子签名服务及 CA 证书。仅画出签名不能等同完整认证签约 | 阅读全文、核对身份和费用、提出审阅意见、双方分别手写、保留冻结版本、下载归档。实名认证和认证电子签章仍需单独接入，当前不宣称已具备 |

## 2. 合同阅读、审阅与签署

主流程：管理员录入草稿 → 全文预览 → 发送双方 → 阅读与关键字段核对 → 处理审阅意见 → 本人手写并明确确认 → 双方签齐 → PDF 归档 → 履行与结算。

1. 合同展示房源、双方、租期、月租、押金、完整条款和签署进度。核对付款、维修、退租等约定时，允许填写条款位置和问题，不必先退出合同去发聊天消息。
2. 意见状态为“待回复、待提出人确认、已解决”。管理员不能替提出人确认。回复仍有疑问时继续反馈，历史交流进入处理记录；任一未解决意见阻止本轮双方签署。
3. 合同正文修改仅在双方均未签时撤回草稿进行。重新发送产生新轮次，旧审阅与旧签署请求不适用于新轮次；历史意见保留用于追溯。
4. 签名保存、个人印章录入和每次盖章分别由本人选择。删除签署资料不改历史合同。印章图片和手写轨迹均限制当前账号使用，已签合同保存副本。
5. PDF 含完整正文、双方签名/印章、时间与校验信息。草稿或未签齐合同标明当前状态，不包装成已完成的合同。
6. 管理工作台提供草稿、待签、已签、临期、续租、退租队列，详情按正文、审阅、信息、履行、处理记录展开；日期使用 Ant Design 日历。

已签合同不应直接覆盖或删除，也不能用后台“代签”解决身份问题。当前账号登录和手写确认不等于第三方实名验证；本阶段未实现 CA 数字证书或可信时间戳。

## 3. 找房、位置和行政区划

行政区划和地图位置分开维护：前者负责省、市、区筛选和规范编码，后者负责真实地图坐标。区划名称不能直接推算成房源坐标。

- 使用已核验的民政部国家行政区划版本，记录来源 URL、数据日期和校验值。直辖市、直管县以及港澳台缺少下级数据的情况明确处理，不编造市县。
- 房源单独录入面向公众的小区/入口名称和 GCJ-02 坐标，地图展示这些公开点位；运营约看集合点独立维护。
- 地图按当前视野、地区、租金及关键词筛选，联动房源列表。重叠点位仍可从列表选择，避免仅依靠点击标记。
- 小区建议根据本站可展示的真实房源去重生成，不假装拥有全国完整小区数据库。定位未授权、坐标未录入时仍能列表找房。
- 导航明确目的地是公开位置还是约看集合点，允许用户在系统地图中选择路线。H5 地图供应商配置和微信定位权限须在发布环境分别验收。

## 4. 运营发布中心

房源 → 生成文案和素材草稿 → 运营预览 → 选择账号与时间 → 按账号排队 → 平台提交/人工待办 → 记录结果。

### 内容与账号

只使用房源中已经维护的数据，不编造“地铁口、学区、最低价”等卖点；不得将租客姓名、签名、电子章、合同附件或私有门牌混入营销素材。租金单位、出租/出售、面积、户型、小区须匹配源房源。

每个平台账号有独立名称、平台、启用状态、接入方式及授权配置引用。平台账号密码和浏览器 Cookie 不进入本系统表单。暂无授权时可建人工账号，先使用 Markdown 文案与图片链接清单、平台创作入口和结果回填；导出内容不包含图片文件 ZIP 包。

### 审核、定时与结果

- 自动生成的草稿须经审核，防止房源信息录入未完成就对外传播。
- 每个目标账号各有任务、计划时间、状态和错误，部分失败不重发已成功账号。
- 同一内容/账号防止重复提交；发布前重新检查源房源是否仍可推广。已租、下架或内容变化不得继续静默发布旧稿。
- 明确失败才能进入重试；网络超时但平台可能已经收到时，先核对外部结果，避免重复发帖。
- 人工导出不等于发布成功，管理员提供实际作品链接后才记录人工发布结果。
- 房源下架后已发布作品无法凭本地状态自动消失，应保留平台作品链接供运营撤下；后续接入平台官方删除能力再实现自动撤下。

### 官方接口边界

抖音官方“创建图文”接口需申请 `video.create.bind` 并取得用户授权，提交后还会经过平台审核；需要遵守其发布能力使用规范，房产营销场景应先确认准入。参见[官方创建图文文档](https://partner.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/video-management/douyin/create-image-text/create-image-text)及[发布能力使用规范](https://partner.open-douyin.com/docs/resource/zh-CN/dop/operation-standard/platform-capabilities/useclue)。

本次未核验到可直接用于所有普通小红书账号的通用服务端笔记发布权限。小红书账号授权文档只证明账号授权能力，不能据此推定发文能力；因此当前采用人工发布交接。后续选择具备正式合同和接口文档的服务商，再补适配器，不以模拟登录或未公开接口假冒官方接入。参见[小红书账号 API 目录](https://openaccount.xiaohongshu.com/docs/api-reference)。

## 5. 交付与上线区分

代码交付须包含数据库迁移、前后端接口、权限菜单、回归测试、构建和远程提交。上线还需要部署后端与后台、发布小程序、执行正式 MySQL 迁移、配置地图服务与平台授权，并由两个真实账号完成签约和一次受控发布验收。

发布中心目前按用户选择交付接入配置，不代表已经绑定社交账号或向任何平台发出房源。第三方认证电子签、在线支付、全国小区商业 POI 库和真实社交账号发布不在已接通能力中。后续优先级由实际使用情况决定，避免用未验证的“全自动”替代可检查的业务结果。
