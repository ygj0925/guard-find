# 地图找房与行政区划接入

## 已实现的流程

- 新增或编辑房源时选择民政部官方行政区划。后台使用 Ant Design Cascader 支持名称搜索，小程序适配直辖市、省直辖县和无市县资料的省级节点。
- 为房源录入独立的 **公开位置**：小区入口或公寓门店名称及 GCJ-02 经纬度。小程序可通过 `uni.chooseLocation` 选点；后台接入腾讯地图官方 iframe 选点组件，校验消息来源域名与 iframe 窗口，防止其他页面伪造坐标。未启用地图组件时仍可手动录入已核实的坐标。
- 首页增加地图找房入口。支持城市、租售、月租/日租、整数价格范围、关键词检索和小区联想。选择联想后按城市、区县、小区精确检索，避免同名小区混在一起。
- 地图和列表互切；点标记可优先展示对应房源，查看详情或调用系统地图导航；拖动地图后点击“搜索此区域”。用户主动点击“我的附近”才申请位置，使用 GCJ-02 获取附近约 10km 宽的矩形范围，不持续追踪定位。
- 只查询上架、未删除、正常接待的房源；未录入公开位置的不出现在地图上。结果最多 200 套，超过时明确提示缩小范围。地图数据不包含详细门牌、房间号、房东联系方式或预约私有说明。

## 版本与兼容

区划采用民政部 2024-12-31 官方快照，共 3213 个代码；**不宣称最新实时区划**。源地址、校验值、可复现导入脚本和更新说明见 backend `resources/china-source.README.md`。2025/2026 官方发布入口本次返回 403，未以未经核验的第三方数据替代。

原表的 32 项省直辖县级名称带 `*` 脚注。导入时依据原表注 2 去除该后缀，保留行政名称正文和原代码；原始官方 HTML 的 SHA-256 不变，规范化数据另行计算 SHA-256。扫描未发现其他脚注符号需要清理。

新增迁移 `property_location_search.sql`，在房源表增加公开经纬度、公开位置名、行政区划代码及查询索引。历史 city/district 文字保留，新选代码时由服务端按官方名称填写。旧房源需要运营核实后补录公开位置，系统不把已有接待集合点自动转换成地图公开标记。

## 上线配置与验收

1. 后端执行 Liquibase 迁移，更新管理后台及小程序。
2. 后台构建环境变量 `TENCENT_MAP_KEY` 填写腾讯地图组件允许使用的 key；小程序 H5 构建环境变量 `VITE_TENCENT_MAP_KEY` 用于 H5 地图展示。配置腾讯控制台应用、域名白名单与额度。这里只能放允许暴露给网页的应用 key，不能放服务端 secret。未配置时页面明确显示地图暂未启用，保留列表检索。
3. 微信端使用平台原生 map/openLocation，manifest 已声明 getLocation、chooseLocation 的用途及所需隐私接口。仍须在微信公众平台核对定位接口开通、用户隐私保护指引并用开发者工具和真机验证；代码声明不等于平台资质已获批准。
4. 实际录入公开入口坐标，在两个城市验证检索、同名小区区县区分、地图标记与列表对应、移动地图后搜索、导航与定位拒绝回退。校验下架/已出租/已售/暂停房源不可检索，未配置 key 的 H5 正常回退。
