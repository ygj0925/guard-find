# 小程序合同、续租与临期提醒上线说明

本次修改涉及 `guard-find-backend`、`guard-find-frontend` 和 `guard-find-miniapp`。独立 App 与记账服务没有新增租赁接口。

## 使用流程

1. 管理员进入“合同与续租”，选择出租房源、房东和租客，填写双方姓名、租期、月租金、押金及完整条款，保存草稿。双方都需要已启用的小程序账号；已有房东归属的房源必须使用对应房东。
2. 核对草稿后发布。发布会固化合同正文及 SHA-256 摘要，之后不能修改条款。相同房源的租期与其他待签或已签合同重叠时，发布会被阻止。
3. 双方通过小程序“我的 → 我的租约”或站内通知进入详情，阅读全文，勾选同意并输入与合同一致的姓名，分别确认。双方均完成后才显示已签订。不同账号不能访问或代签他人合同。
4. 未完成双方签订的合同可以拒签或由后台作废，已签订合同只能由有权限的管理员记录原因后终止。草稿、待签或有效合同未处理前，不允许直接删除关联房源。
5. 承租人在续租窗口内提交期望结束日期和说明，也可在审核前撤回。后台批准后生成关联的续租草稿；管理员核对金额、日期和条款后发布，双方重新签订。原合同和签订记录保持保留，作废续租草稿或待签合同后可重新申请。
6. 承租人可提交退租意向，由后台记录处理结果。退租申请不会自动终止合同，也不会自动办理退押金；已批准的续租合同与退租申请不能同时推进。

小程序可复制合同全文及确认记录；后台可导出文本。记录包含条款摘要、双方确认时间和操作日志。当前实现是登录账号的确认记录，没有接入外部实名认证、CA 证书、可信时间戳或第三方电子签章服务。合同条款由运营人员核实后填写，系统不自动生成可直接使用的法律文本。

## 临期提醒

- 默认启用站内通知，提前 30、7、1 天及到期当天提醒双方；后台可调整提醒天数、续租窗口或关闭提醒。
- 默认续租窗口为到期前 90 天，过期后联系管理员处理。
- 服务启动 90 秒后执行首轮扫描，随后每小时扫描一次，每批最多 500 份合同。提醒记录用于去重，后续批次会继续处理尚未提醒的合同。
- 停机恢复时，按当前最接近的提醒节点补发一次，不补发所有历史节点；最多补查最近 30 天已到期合同。
- 每份合同的双方站内通知和提醒记录在同一事务内提交，发送失败回滚并由后续扫描重试。
- 本次未启用合同微信订阅推送。现有预约订阅模板不能用于合同到期提醒；微信模板与外部签章服务需要后续独立接入。

## 部署与权限

1. 备份数据库，部署后端，由 Liquibase 执行 `property_lease_workflow.sql`。迁移新增合同、操作记录、提醒记录、配置表及菜单，不改写既有房源、预约和已发布协议。
2. 部署管理后台，重新登录刷新权限。新权限包括 `system:property:lease:list/create/update/publish/terminate`；发布与续租批准使用发布权限，作废与终止使用终止权限，提醒设置及申请处理使用编辑权限。
3. 迁移会参照既有房源查看、编辑和上下架授权初始化对应合同权限。运营负责人应按岗位检查最终权限配置。
4. 编译发布小程序，确认“我的租约”入口和 `PROPERTY_LEASE` 通知跳转。后端与管理后台应先于小程序上线。
5. 以两个独立测试账号完成一次发布、双方确认、续租申请、审核、新合同签订及退租处理，并确认提醒配置和站内消息。服务器应使用业务时区（当前运营为 Asia/Shanghai），合同日期按服务器日期计算。

所有变更包含版本校验，页面停留期间合同发生变化时，需要刷新后再操作。小程序切换账号或离开详情后，旧请求不能重新写入合同或预约联系人资料。

## 验证与边界

自动检查覆盖合同权限、双方确认、正文一致性、租期冲突、续租关联、事务回滚、并发操作、提醒去重与分批处理，以及两端主要交互。后端测试需显式使用 `-DskipTests=false`，项目默认跳过测试。

本次后端相关测试 88 项、后台相关测试 26 项通过；小程序全量 313 项及补充的 5 项回归通过，共验证 318 项不同用例。两端类型检查、后台接口/权限/菜单契约检查、两端最终生产构建通过。小程序构建仍会报告既有的浏览器兼容数据过期、`carbon-door` 和 `carbon-lounge` 图标提示。

代码推送不等于生产部署。本地自动测试和构建不替代正式 MySQL 升级、微信开发者工具及真机联调。
