# Guard Find 项目结构说明

## 工作区边界

```text
Guard Find 工作区
├─ guard-find-app       用户端移动/Web 应用
├─ guard-find-server    用户侧 Java 服务
├─ guard-find-frontend  管理后台 Web 前端
└─ guard-find-backend   管理后台 Java 服务
```

用户请求流为 `guard-find-app → guard-find-server`；后台运营请求流为 `guard-find-frontend → guard-find-backend`。两套服务端使用独立 Maven GAV、Java 根包、数据库、Redis、Compose 项目和容器端口，可在同一开发主机或部署主机并行运行。

## 用户侧服务：guard-find-server

- 根 Maven 制品：`com.guardfind.server:guard-find-server`。
- Java 根包：`com.guardfind.server`。
- 主启动类：`com.guardfind.server.GuardFindServerApplication`。
- 调度启动类：`com.guardfind.server.extension.scheduling.GuardFindServerScheduleApplication`。
- 主 API 模块：`guard-find-server-api`；thin jar 输出目录为 `guard-find-server-api/target/app/`。
- 支持模块：`guard-find-server-system`、`guard-find-server-common`、`guard-find-server-plugin` 及其 `guard-find-server-plugin-*` 子模块、`guard-find-server-extension` 及其调度子模块。

```text
guard-find-server/
├─ guard-find-server-api/                 主 API、配置、Liquibase 与部署产物
├─ guard-find-server-system/              认证和系统管理能力
├─ guard-find-server-common/              CRUD 与跨模块基础设施
├─ guard-find-server-plugin/              open、tenant、schedule、generator 插件
├─ guard-find-server-extension/           独立调度扩展
└─ docker/                                guard-find-server Compose 与镜像构建上下文
```

Compose 项目名为 `guard-find-server`，数据库为 `guard_find_server`。为了避免与后台服务碰撞，MySQL、Redis、API、调度端口分别为 `13306`、`16379`、`18000/17889`、`18001/17888`。

## 管理后台服务：guard-find-backend

- 根 Maven 制品：`com.guardfind.backend:guard-find-backend`。
- Java 根包：`com.guardfind.backend`。
- 主启动类：`com.guardfind.backend.GuardFindBackendApplication`。
- 调度启动类：`com.guardfind.backend.extension.scheduling.GuardFindBackendScheduleApplication`。
- 主 API 模块：`guard-find-backend-api`；thin jar 输出目录为 `guard-find-backend-api/target/app/`。
- 支持模块：`guard-find-backend-system`、`guard-find-backend-common`、`guard-find-backend-plugin` 及其 `guard-find-backend-plugin-*` 子模块、`guard-find-backend-extension` 及其调度子模块。

```text
guard-find-backend/
├─ guard-find-backend-api/                主后台 API、配置、Liquibase 与部署产物
├─ guard-find-backend-system/             RBAC、菜单、租户和系统管理
├─ guard-find-backend-common/             CRUD 与跨模块基础设施
├─ guard-find-backend-plugin/             open、tenant、schedule、generator 插件
├─ guard-find-backend-extension/          独立调度扩展
└─ docker/                                guard-find-backend Compose 与镜像构建上下文
```

Compose 项目名为 `guard-find-backend`，数据库为 `guard_find_backend`。MySQL、Redis、API、调度端口分别为 `23306`、`26379`、`28000/27889`、`28001/27888`，不会与用户侧服务的默认容器映射重叠。

## 构建与运行

分别在两个工程根目录运行：

```powershell
mvn -B -Dspotless.apply.skip=true -DskipTests package
```

也可在 IDE 中直接运行各自的主启动类。主服务依赖 MySQL、Redis 和可选 SnailJob 调度服务；连接参数通过 `DB_*`、`REDIS_*`、`SCHEDULE_*` 与 `PROFILES_ACTIVE` 环境变量配置。请为两套服务维护独立的数据库、Redis 命名空间、对象存储路径、认证客户端与生产密钥。

## 模板与第三方归因

两个服务保留 Apache-2.0 许可证、原有许可证头以及第三方 `top.continew.starter` 依赖。`top.continew.starter`、`ContiNewStarterVersion` 和 `continew-starter.*` 配置键为外部 starter 的公开名称，未参与内部重命名。Guard Find 内部模块、包路径、启动类、部署服务和构建产物均使用对应的 `guard-find-server-*` 或 `guard-find-backend-*` 命名。
