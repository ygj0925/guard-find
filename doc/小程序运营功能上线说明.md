# 小程序与管理后台运营功能上线说明

本次功能面向 `guard-find-miniapp`、`guard-find-frontend` 和 `guard-find-backend`。`guard-find-app` 与 `guard-find-server` 使用独立业务数据，不随此次运营工作流合并。

## 已补齐的流程

- 预约：待确认、已确认、已拒绝、已取消、已到访、已完成、未到访、已过期；支持改期、原因记录、处理日志和预约详情跳转。
- 接待：房东归属和服务管家分开配置；支持停止接待、已出租、已售出、重新开放日期、集合地点、看房说明和地图坐标。
- 用户：搜索选择小程序用户、停用/启用账号、认证/取消服务管家。
- 客服：认领、转交、解决、重新打开、内部备注、来源房源和处理记录。内部备注不返回给小程序用户。
- 运营：浏览、咨询、预约、到访、完成统计，日趋势、房源统计和管家工作量。统计为上线后收集的事件，浏览按用户/房源/分钟去重，不等同于独立访客数。
- 政策：后台配置运营主体、联系方式、协议内容、版本和生效日期；发布后记录用户同意的版本。未发布时不展示虚构运营资料。
- 微信订阅提醒：提供配置、用户主动授权、一次性额度、待发送队列和发送结果记录；默认关闭。

## 部署顺序

1. 备份数据库，先部署后端，让 Liquibase 执行 `property_operations_workflow.sql`。迁移创建运营工作流表和菜单，保留既有房源与预约。
2. 部署管理后台。根据岗位检查“运营统计”“小程序用户”“运营配置”“客服工单”菜单及按钮权限，重新登录刷新权限缓存。客服主管的跨人处理权限需单独授权。
3. 编译发布小程序。预约通知会进入预约详情，客服会话能展示用户咨询的房源。
4. 在测试环境验证预约提交、确认、改期、取消、到访、完成，以及客服认领/转交流程，再发布正式环境。

房源的停止接待状态会阻止新预约，不会自动取消已存在的预约。后台会显示进行中的预约数量，运营人员应逐笔联系并处理已有预约。

## 当前配置

尚未提供正式运营主体、客服电话/邮箱和微信订阅模板 ID。因此不预填虚构资料，协议保持未发布，微信订阅提醒保持未启用。站内通知仍可使用。

实际资料准备后，在“运营配置”填写完整协议和版本并发布。只有完整配置通过校验后才可发布。

微信订阅需同时具备后端 `miniapp.wechat.app-id`、`miniapp.wechat.app-secret` 和已获批模板。密钥只配置在服务端，不填写到后台页面或小程序代码。后台填写模板 ID 和对应的标题 `thing`、预约时间 `time`、状态 `phrase` 字段名，确认一致后再启用。小程序需由用户主动点击授权；拒绝或没有授权时不会发送订阅消息。

发送记录可能为 `DISABLED`（未启用）、`PENDING`（待发送）、`NO_CONSENT`（无可用授权）、`SENDING`、`SENT`、`FAILED` 或 `UNKNOWN`。网络超时和进程中断后无法确认微信是否收到时标记 `UNKNOWN`，不自动重发，避免重复发送。

## 验证边界

自动测试覆盖业务权限、状态流转、并发版本检查、事务回滚、内部备注隔离、默认关闭配置和前端主要交互。正式数据库升级、真实微信模板授权/下发以及生产域名联调，需要部署环境及正式资料后验证。

本次验证结果：后端相关测试 75 项、小程序全量测试 293 项、后台相关测试 20 项均通过；两端类型检查、后台接口/权限/菜单契约检查和两端生产构建通过。小程序构建仍提示既有的 `carbon-door`、`carbon-lounge` 图标缺失和浏览器兼容数据过期。

后端默认跳过测试，复测需显式传入 `-DskipTests=false`：

```powershell
# guard-find-backend
mvn -pl guard-find-backend-system -am test -DskipTests=false -Dtest=PropertyOperationsTest,PropertyRegressionTest,MiniappAuthTest,ImRegressionTest -Dsurefire.failIfNoSpecifiedTests=false
# guard-find-miniapp；限制并发，避免本机负载过高造成超时
pnpm exec vitest run --maxWorkers=2 --testTimeout=30000
# guard-find-frontend
npm test -- --runInBand --testTimeout=60000 tests/propertyOperations.test.tsx tests/propertyForm.test.tsx tests/supportMessages.test.tsx tests/supportConversations.test.tsx
npm run check:contract:ci
```
