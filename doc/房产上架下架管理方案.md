# 房产上架下架管理方案

## 一、市场调研（贝壳/链家/安居客/58 同城）

核心共识：
| 能力 | 说明 |
| --- | --- |
| 房源 CRUD | 标题/描述/价格/面积/户型/楼层/朝向/装修/地址/联系方式 |
| 图片管理 | 多图上传(≤9),首图为封面 |
| 状态流转 | 草稿 → 已上架 → 已下架(可重新上架) |
| 设施配套 | 电梯/停车位/阳台/洗衣机/空调/热水器/宽带 等结构化标签 |
| 浏览计数 | 只增不减,衡量曝光 |

## 二、权限矩阵
| 能力 | 发起人(房东) | 其他登录用户 |
| --- | --- | --- |
| 创建房源 | ✓ | ✗ |
| 编辑/删除自己的房源 | ✓ | ✗ |
| 上架/下架 | ✓ | ✗ |
| 浏览已上架房源 | ✓ | ✓ |
| 浏览自己的草稿/已下架 | ✓ | ✗ |

## 三、表结构

### gf_property(房源主表)
id / user_id / title / description / property_type(house/apartment/villa/shop) / layout(户型)
area_sqm / floor_info / orientation / decoration(毛坯/简装/精装/豪装)
price / price_type(rent/sale) / address / district / city
facilities(JSON 数组) / contact_name / contact_phone
status(1 草稿 / 2 已上架 / 3 已下架) / view_count / images(JSON 数组 ≤9)

### 状态流转
DRAFT(1) → LISTED(2) → DELISTED(3) → LISTED(2)(可重新上架)
草稿不对外可见,下架后已上架用户仍可见但标"已下架"。

## 四、API
POST /app/property — 创建房源
GET /app/property/list — 广场(已上架,分页)
GET /app/property/mine — 我的房源(全部状态)
GET /app/property/{id} — 详情(浏览计数+1)
PUT /app/property/{id} — 编辑(仅本人)
DELETE /app/property/{id} — 删除(仅本人)
POST /app/property/{id}/status — 上架/下架(仅本人)
