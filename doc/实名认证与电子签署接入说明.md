# 实名认证与电子签署接入说明

本次实现把合同业务、身份核验和签署审计拆成三个层次：合同模板和签署记录继续由本系统保存，身份核验通过统一适配器接入，签署时由后端再次校验核验状态。小程序和管理后台都只使用状态和脱敏信息，不把身份证原图、人脸原图或视频写入合同业务表。

## 默认状态

数据库初始化后实名认证为 `DISABLED`。此时小程序会明确提示“实名认证服务尚未启用”，但不会把登录账号或手写签名标记为已实名认证，也不会阻断原有签署流程。

## 当前可用模式

- `MANUAL`：小程序在签署前单独取得身份信息处理同意，提交姓名和身份证号格式信息；后台仅看到脱敏号码和核验记录，工作人员线下核对证件后在“实名认证”页人工通过或拒绝。后端会记录复核人、复核时间、原因和版本号。
- `PROVIDER`：后端通过 `IdentityVerificationProvider` 创建外部核验会话，并把服务商返回的短期页面地址交给小程序打开。核验完成后需要由服务商适配器回写结果，后端才允许签署。
- `DISABLED`：不执行实名认证门禁。

当前仓库内置的是安全的 `UnavailableIdentityVerificationProvider` 占位实现。它不会伪造通过结果；如果在没有接入服务商 SDK、接口和密钥的情况下选择 `PROVIDER`，会返回“服务尚未配置”，用户无法被标记为已通过。正式接入腾讯云或阿里云时，实现 `IdentityVerificationProvider`，把密钥放在部署环境的密钥管理中，不写入数据库或前端代码，并补充服务商回调验签、超时、重试和幂等处理。

## 签署门禁

管理后台打开“签署前必须通过核验”后，合同 `SIGN` 操作会在后端检查当前用户的有效核验记录和有效期。小程序提交签署时会带上当前核验会话号；即使绕过前端，后端也不会接受未通过、已拒绝或已过期的记录。核验有效期默认 365 天，可在后台配置 1 至 3650 天。

## 上线前检查

1. 确认隐私政策、身份核验目的、保存期限和用户撤回渠道，并在小程序上线前完成相应的个人信息合规配置。
2. 先使用 `MANUAL` 模式跑通同意、提交、人工复核、签署门禁和拒绝重试流程。
3. 选定腾讯云或阿里云后，在后端实现对应适配器和回调验签，配置正式密钥、回调地址和服务商业务备案，再切换 `PROVIDER`。
4. 生产环境开启 HTTPS、数据库备份加密、访问审计和最小权限；管理后台始终只展示脱敏身份证号。
5. 电子合同是否具有可靠电子签名效力，还取决于实名结果、签署人控制、签署后内容完整性、日志留存和争议举证。当前系统的手写签名功能本身不等同于第三方 CA 电子签名证书，不能直接宣称达到贝壳等平台的同等认证强度。
